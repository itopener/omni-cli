# omni-cli v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现 `omni-cli` v1：面向 AI 的 `db`/`redis` 统一命令入口，用 Go 原生驱动直连 MySQL/PostgreSQL/Redis（不依赖系统已装客户端），直连（`type: tcp`），配置全走 CLI 管理。

**Architecture:** Go + cobra，`internal/` 分层：`conn`（连接方式策略，叶子包）→ `config`（配置加载/解析）→ `db`（database/sql + go-sql-driver/pgx）与 `redis`（go-redis）→ `output`（table/json 渲染）→ `schema`（机器可读字段清单）。每次命令短连接，`defer Close`，池大小 1，`--timeout` 贯穿 ctx。

**Tech Stack:** Go 1.22+，`cobra`，`gopkg.in/yaml.v3`，`github.com/go-sql-driver/mysql`，`github.com/jackc/pgx/v5`，`github.com/redis/go-redis/v9`（全部纯 Go，`CGO_ENABLED=0`）。

**Spec:** `docs/design.md`

## Global Constraints

- Go 1.22+，`CGO_ENABLED=0`；module path 暂定 `omni-cli`。
- 依赖仅上列 5 个，禁止新增。
- **无魔法值**：字段名只出现在 struct 的 yaml/json tag 与 cobra flag 定义两处；`type`/`driver` 用 typed 常量（`conn.ConnType*`、`db.Driver*`）。
- **安全**：secret（密码/令牌）只在内存（驱动的 DSN/Options），不打印、不落日志/错误/测试。
- **连接生命周期**：Open → 执行 → `defer Close`；db `SetMaxOpenConns(1)`，redis `PoolSize=1`；查询用 `context.WithTimeout`（`--timeout` 默认 30s）。
- **AI 友好**：`--help`、错误信息、`config schema` 是产品接口；schema 从代码生成。
- **跨平台**：路径用 `filepath`；无子进程、无 shell 依赖。
- 错误 `fmt.Errorf("...: %w", err)` 包裹；库代码不 panic；表驱动测试；`go test ./...` 全绿。
- 提交 Conventional Commits，末尾加 `Co-Authored-By: Claude Code <noreply@anthropic.com>`。

## Review Focus

1. **空密码**：空密码不生成空 auth（mysql `Passwd=""`、redis `Password=""` 即不启用鉴权）→ Task 4、5。
2. **数字字段以字符串传入**（CLI `--param port=3306`）：`port`/`db` 字符串→int 强转，非数字报错 → Task 1。
3. **同 key 多环境、未指定 `-e`**：报错并列出可用 env → Task 3。
4. **未知 `type`/`driver`**：报错并列出合法选项 → Task 1（type）、Task 4（driver）。
5. **`${VAR}` 变量未设置**：报错，不静默换空串 → Task 2。
6. **密码含特殊字符**（`@`/`:`/`/`）：DSN 用驱动 Config 构造（`mysql.Config.FormatDSN`），不手拼字符串 → Task 4。
7. **连接不 Close / 查询卡死**：`defer Close` + 池=1 + ctx 超时，超时/取消中断查询回收连接 → Task 4、5。
